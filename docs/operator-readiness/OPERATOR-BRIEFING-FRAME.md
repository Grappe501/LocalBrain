# Operator Briefing Frame

> **Audience:** Internal operators (Kelly, Chris, campaign staff)  
> **Do not use:** Architecture tours · feature demos · "help us test" framing

---

## What to say

Do **not** tell the operator they are testing software.

Tell them:

> **"Pretend it's six months from now and this is your everyday job."**

That changes behavior. People stop trying to help the test. They simply try to accomplish the work.

That is the evidence we want.

---

## What the operator receives

| Item | Purpose |
| ---- | ------- |
| Scenario brief | [OPERATOR-WALKTHROUGH-001 — County Fair Return](./WALKTHROUGH-001-SCENARIO.md) (operator-facing sections only) |
| Fixture access | [county-fair-volunteers.csv](./fixtures/county-fair-volunteers.csv) |
| Workspace | Pre-loaded test environment — no setup required |

**Do not provide:**

- Navigation maps
- Architecture overviews
- Terminology glossaries before the session
- Expected outcomes or "correct" paths

---

## What the operator should know

1. This is a realistic work scenario — county fair volunteer intake through trusted relationship.
2. Think aloud if helpful; a scribe is capturing what happens.
3. Ask clarifying questions about the **work**, not the **software design**.
4. If stuck, say so — that is valuable evidence.
5. There is no grade. There is no pass/fail performance review.

---

## Session roles (invisible to operator)

| Role | Visible to operator? |
| ---- | -------------------- |
| Operator | Yes — they are doing the work |
| Facilitator | Yes — quiet observer; minimal prompts only |
| Evidence Scribe | Preferably low-profile — "I'm taking notes on the workflow" |

The operator should experience **a work session**, not a lab study.

---

## After the session

The operator may answer reflection questions (see [Facilitator Card](./OPERATOR-SESSION-FACILITATOR-CARD.md)).  
They do **not** participate in evidence interpretation or product discussion in the same meeting.

Thank them. Close the session. Analyze later.
